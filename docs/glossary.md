# 용어집과 경계선

화면(UI)과 1005 기능명세서에서 쓰는 말을 기준으로 정리한 용어집이다. 문서(`api-spec.md` 등)는 이 표의 **화면 용어**를 쓰고, URL·필드·DB 이름은 코드 이름 열을 그대로 쓴다.
기준: `기능명세_1005.pdf`(2026-10-05 결정), 유저 플로우, 와이어프레임. 용어가 서로 다르면 1005 명세를 따랐다.

## 1. 용어

| 개념 | 화면·명세 용어 | 코드 이름 (URL·필드·DB) | 설명 |
| --- | --- | --- | --- |
| 가족 단위 | **가족방** | `groups`, `group_id`, `family_group` | 구성원이 소식을 올리는 단위. "가족 없음" 대신 "가족방 없음 화면" (ACC-01) |
| 만든 사람 | **방장** | `OWNER`, `owner_id` | 가족방을 처음 만든 사람. 방장 기능은 가족 탭의 "가족 설정" (FAM-08) |
| 구성원 | **구성원** | `MEMBER`, `family_member` | 가족방에 참여 중인 사람 |
| 소식을 받는 분 | **받는 분** | `recipient`, `delivery_address` | 조부모. 앱에 로그인하지 않고 신문만 받는다 (RCV-01) |
| 가족방 이름 | **가족방 이름** | `name` | 앱 안에서 가족을 부르는 이름. **신문에 실리지 않는다** (FAM-02) |
| 신문 제호 | **신문 제호** (신문 이름) | `newsletterTitle`, `newsletter_title` | 지면의 제목. 기본값 `보고잡지` (FAM-03) |
| 서비스명 | **보고잡지** | - | 안내 문구에 고정으로 쓴다. 가족방 이름·제호와 별개 (HOME-02) |
| 글 | **소식** (소식 탭), **게시물** (소식과 답변을 아우르는 말) | `post` | 사진과 짧은 글. 명세도 "게시물·답변"으로 함께 쓴다 (POST-01, POST-07) |
| 질문 | **질문카드** (탭 이름), **질문** | `question`, `issue_question` | 매주 월요일 07:00 공개 (QST-01) |
| 질문에 대한 글 | **답변** | `answer` (`post`에서 `question_id`가 있는 것) | 질문카드 안에서 작성 (QST-03) |
| 답변에 다는 글 | **댓글** | `comment` | 답변에만 달 수 있고 1단계 (QST-06) |
| 공개 범위 | **가족 전체**, **할머니께만** | `ALL`, `RECIPIENT_ONLY` | "할머니께만"은 호칭이 받는 분에 따라 바뀜 (POST-02, TTL-01) |
| 호 | **호** (제 N호) | `issue` | 정해진 기간에 모은 소식·답변으로 만드는 신문 한 부 |
| 얼굴 | **캐릭터** | `character` | 앱 아바타와 지면 표기에 쓴다. 사진은 받지 않는다 (PRF-05) |
| 신문 표기명 | **관계 + 이름** + 캐릭터 | `label`, `character` | 예: 손녀 보민 (PRF-03) |
| 받는 분과의 관계 | **관계** | `relationship` | 8개 값 중 하나. 가족방마다 따로 저장 (PRF-02) |
| 초대 | **초대 링크** | `invite-link` | 카카오톡 링크만. 가족방마다 1개 (FAM-05) |
| 방장이 제외한 사람 | **내보낸 구성원** | `removed-members`, `family_block` | 방장이 내보내면 이 목록에 들어가고 같은 링크로 재합류할 수 없다. 재합류는 방장이 허용 (FAM-09·10) |
| 내 화면에서 숨김 | **차단** (개인 차단) | `user_block`, `/users/{id}/block` | 내 화면에서만 숨기고 팀에 자동 신고 (SAFE-02) |
| 부적절한 글 알림 | **신고** | `report` | 사유 선택 후 제출 (SAFE-01) |
| 운영 화면 | **Admin** | `/admin` | 사람은 **운영자** (ADM-01) |
| 신문 열람 | **신문 보기** | `newsletter` | 발송 완료 후에만 가능 (PUB-02) |
| 대기 신청 | **대기 신청** | `waitlist` | 정식 출시 때 알림을 받는 신청 (WAIT-01) |

## 2. 호 상태 (단일 출처)

호 상태는 **내부 상태(`phase`)** 하나를 원천으로 두고, 사용자에게 보이는 **표시 상태(`displayState`)**는 서버가 매핑해서 만든다 (2026-10-06 확정, C안). 표시가 명세에 따라 바뀌어도 내부 상태는 흔들리지 않게 하려는 구조다.

| 내부 `phase` (운영자 API) | 의미 | 전환 | 표시 `displayState` (사용자 API) | 상태 줄 (HOME-02) | 현재 DB `issue.status` |
| --- | --- | --- | --- | --- | --- |
| (호 없음 또는 시작 전) | 앱 화면 상태 | - | `BEFORE_START` | 작성 가능 시작일 | 호 없음 |
| `COLLECTING` | 모집 중 | 호 시작 | `COLLECTING` | 마감 D-day | `collecting` |
| `CLOSED` | 마감 시각이 지남. 사진 있는 글은 +14분까지 등록, +15분부터 조판 대기 | 자동 | `PRODUCING` | 신문 만드는 중 | `closing` |
| `COMPOSING` | 조판 큐 대기·실행·재시도 대기, 재조판 | 자동 | `PRODUCING` | 신문 만드는 중 | `closing` |
| `COMPOSE_FAILED` | 3회 실패, 운영자 조치 필요 | 자동 | `PRODUCING` | 신문 만드는 중 | `closing` |
| `IN_REVIEW` | 운영자 검수 | 자동 (조판 완료) | `PRODUCING` | 신문 만드는 중 | `review` |
| `SENT` | 발송 완료 | **운영자 수동** | `SENT` | 신문 보기 · 다음 호 신청 | `printed`, `archived` |

- 사용자 API는 `displayState`만 내려주고 내부 이름은 운영자 API에만 있다.
- 허용 전이: `COLLECTING → CLOSED → COMPOSING → IN_REVIEW → SENT`, `COMPOSING → COMPOSE_FAILED`, `COMPOSE_FAILED → COMPOSING`(재시도), `IN_REVIEW → COMPOSING`(재조판). **`SENT`는 되돌릴 수 없다.**
- 조판이 실패해도 사용자에게는 계속 "신문 만드는 중"으로 보인다. `COMPOSE_FAILED`는 운영 알림(ADM-08)이 유일한 신호다.
- 명세에 없는 DB 값 `skipped`, `archived`, `printing`은 없앤다. 이전 `step` 값 `CLOSE_FAILED`, `PREFLIGHT_FAILED`는 `COMPOSE_FAILED`에 포함한다.
- 호 상태(`issue.status`)와 조판 작업 상태(`layout_run.status`)는 서로 다른 값이다. 조판 작업의 세부(대기, 실행, 실패)는 `layout_run`이 맡는다.

운영 마커 (표시용, 상태 전환 조건이 아님)

| 마커 | 값 | 비고 |
| --- | --- | --- |
| `reviewed` | 운영자가 "검수 완료" 표시 | 재조판하면 초기화 |
| `printDownloaded` | 인쇄용 PDF 일괄 다운로드 기록에서 파생 | 입력 값이 아님 |

발송 완료 전환(2-b): 사전 점검(`ship-check`)과 확인 화면(`confirmed`)을 거친다. 필수 점검에 실패하면 전환할 수 없고, 경고(마커 미표시, PDF 다운로드 기록 없음)는 확인 후 전환할 수 있다. 푸시가 이미 나가므로 취소는 없다.

| 본인 글 수정·삭제 (마감 전) | O | O | - |
| **남의 글 수정·삭제** | X | **X** (신고·차단만, POST-06) | X (신고 처리로 숨김만) |
| 초대 링크 공유 | O | O | - |

| 받는 분 정보 수정, 배송지 조회·수정 | X | O | 열람만 (열람 기록이 남음) |

## 4. 구분해야 하는 짝

| 짝 | 구분 |
| --- | --- |
| 가족방 이름 / 신문 제호 / 서비스명 | 앱 안에서 부르는 이름 / 지면의 제목(기본 `보고잡지`) / 안내 문구의 고정 이름 |
| 차단 / 내보내기 / 신고 | 내 화면에서 숨김(개인) / 방장이 가족방에서 제외 / 운영자에게 알림 |
| 신문 보기 / 미리보기 | 신문 보기는 **발송 완료 후** 완성본. "미리보기"는 호칭·신문 이름을 고를 때 화면의 문구(TTL-01)에만 쓴다 |
| 소식 / 게시물 / 답변 | 소식 탭에 올리는 글 / 소식과 답변을 아우르는 말 / 질문카드에서 쓰는 글 |
| 모집 마감 / 신문 만드는 중 | 마감 직후 자동 조판 중 / 조판 후 운영자 검수·인쇄 중. 앱 상태 줄에서는 함께 표시 |
| 내부 상태(`phase`) / 표시 상태(`displayState`) | 시스템이 관리하는 6개 상태 / 사용자에게 보이는 3개 + 시작 전 |
| 호 상태 / 조판 작업 상태 | 호 단위의 진행 상태 / 워커가 처리하는 작업 단위 (`layout_run`) |
| 방장 / 운영자 | 가족방의 관리자 / 팀의 Admin 계정. 서로 권한이 겹치지 않는다 |

## 5. 쓰지 않는 말

| 쓰지 않는 말 | 대신 쓰는 말 | 이유 |
| --- | --- | --- |
| 그룹, 가족 그룹, 가족 공간 | 가족방 | 화면 용어는 가족방이다 (코드 이름 `groups`, `family_group`은 유지) |
| 수신자 | 받는 분 | 화면 용어. 코드 이름 `recipient`는 유지 |
| 가제트 이름 | 가족방 이름 / 신문 제호 | 두 개념이 분리됨 (FAM-02, FAM-03) |
| 프로필 사진, 얼굴 사진 | 캐릭터 | 사진은 받지 않음 (PRF-01) |
| 시범 종료 선택 | 대기 신청 | 1005 명세는 대기 신청 버튼 하나 (WAIT-01) |
| 차단 목록 (가족방 쪽) | 내보낸 구성원 | 개인 차단과 구분 |
| 완성본 미리보기 | 신문 보기 | 발송 전에는 볼 수 없다 (PUB-02) |

와이어프레임에 남아 있는 "가제트 이름", "시범 종료 선택", "완성본 미리보기" 같은 표현은 위 용어로 고쳐야 한다. 차이는 [api-spec.md 부록 F-1](api-spec.md#부록-f-확인이-필요한-항목)에 있다.
